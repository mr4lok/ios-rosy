## 3. The permission path in the kernel (traced to the exact line)

`mkdir` -> `vn_authorize_mkdir()` (bsd/vfs/vfs_subr.c:8305)
 -> `vnode_authorize(dvp, KAUTH_VNODE_ADD_SUBDIRECTORY)` -> `vnode_authorize_callback_int`
 -> `vnode_authorize_simple` -> `vnode_authorize_posix`

`vnode_authorize_posix()` (vfs_subr.c:~1300) computes, for the *parent directory*:
```
owner_ok = (needed & vap->va_mode) == needed;   // VWRITE -> S_IWUSR
group_ok = (needed & vap->va_mode) == needed;   //            S_IWGRP
world_ok = (needed & vap->va_mode) == needed;   //            S_IWOTH
```
For mode 0711 (rwx--x--x) with VWRITE needed: owner_ok = 1, group_ok = 0, world_ok = 0.
Then: `if (!owner_ok && !group_ok && !world_ok) return EACCES;` -> not taken.
Then: `if (vauth_file_owner(vcp)) { if (!owner_ok) return EACCES; }` -> **allow if owner**.

`vauth_node_owner()` (vfs_subr.c) is the whole decision:
```c
if (vap && VATTR_IS_SUPPORTED(vap, va_uid))
    result = (vap->va_uid == kauth_cred_getuid(cred)) ? 1 : 0;
```
So **EACCES happens if and only if `va_uid != cred uid`** (given mode 0711 and no ACL).

HFS supplies those attrs in `get_vattr_data_for_common_attrs()` (sweet_hfs/core/hfs_attrlist.c:1485):
```c
uid_t nuid = cap->ca_uid;
if (!isroot) {
    if (vfs_flags(HFSTOVFS(hfsmp)) & MNT_UNKNOWNPERMISSIONS) nuid = cuid;
    else if (nuid == UNKNOWNUID) nuid = cuid;      // UNKNOWNUID = 0xfffffffe
}
vap->va_uid = nuid;   VATTR_SET_SUPPORTED(vap, va_uid);
...
vap->va_mode = (cap->ca_uid == UNKNOWNUID) ? cap->ca_mode & ~(S_ISUID|S_ISGID) : cap->ca_mode;
```
Note `MNT_UNKNOWNPERMISSIONS` is NOT set (mount flags 0x480d0000; MN... bit not present).

## 4. Hypotheses, ranked

H1 - **the caller is not uid 501.** accountsd's job says `UserName=mobile`, but if the
   directory-service lookup for "mobile" fails in this port, launchd may run the job as a
   different uid (or the process may haveuid != 501 after some setup). Then owner_ok is
   computed but `vauth_file_owner` is false -> group_ok/world_ok both false -> **EACCES**.
   Fits the symptom exactly, and explains why it is not reproducible from the image alone.

H2 - **ca_uid for /var/mobile/Library is UNKNOWNUID (0xfffffffe)** in the *phone's* volume.
   Linux's hfsplus shows 501, but Linux maps unknown uids; and the phone's volume has been
   written by XNU. If ca_uid were 0xfffffffe then nuid = cuid (501) -> owner -> allow. So this
   hypothesis actually *predicts success* unless `isroot` is true. Low.

H3 - **the phone's userdata volume is in a state where the catalog entry for that directory
   is not what the image had** (the pre-tweak boots ran on a volume XNU had been writing for
   hours; the re-flash replaced it). The pre-tweak/post-tweak correlation is exact, and the
   image diff shows no /var permission change - so the difference is the *volume instance*,
   not the file bytes. Medium.

H4 - **MNT_UNKNOWNPERMISSIONS or a similar mount flag differs at runtime.** Ruled out by the
   log (identical mount flags 0x480d0000 pre/post).

H5 - **the pre-tweak boots never reached accountsd's DB init** (the data migration stalled the
   system for an hour, so accountsd was blocked before `ACDServerCreateDirectory`), and my
   migration-skip tweak *unmasked* a pre-existing bug. This is very plausible and means the
   tweak is not the cause. Medium-high.

H6 - **a data-protection / keybag interaction** ("MKBUserSessionNeedsMount = 1"): the user
   session mount never happens, so writes that require a mounted user session are refused.
   The error would normally be EPERM/EACCES. Medium.

## 5. Fixes prepared (artifacts, not applied)

### F1 - diagnostic kernel patch (decisive, one boot)
`xnu/patches/1004-rosy-hfs-create-trace.patch`: IOLog in `hfs_vnop_mkdir` / `hfs_makenode`
(errno, caller uid, parent ca_uid/ca_mode/ca_flags, vfs_flags) and in `vn_authorize_mkdir`
(the deny result). Boot26 + this patch prints the actual reason.

### F2 - permissive-permissions kernel patch (bring-up hammer)
Make the parent's `va_uid` compare equal to the caller and force owner rights, i.e. in
`get_vattr_data_for_common_attrs` set `nuid = cuid` unconditionally (like
MNT_UNKNOWNPERMISSIONS does) and keep ca_mode. That turns every directory into "owned by the
caller", so mkdir/create succeed. Same spirit as upstream patch 0050 (permissive MAC policy).

### F3 - image: pre-create the runtime directories
`tools/rosy-mkdirs.py`: create /private/var/mobile/Library/Accounts (and the other
crash-looping daemons' dirs) world-writable, 501:501. Tests H3/H5 cheaply.

### F4 - launchd: run accountsd as root
Set `UserName=root` for com.apple.accountsd in launchd.plist. `vfs_context_issuser` then
short-circuits the POSIX check (is_suser -> allowed). One-line image tweak; bypasses H1/H3.

### F5 - re-flash a pristine image and boot (control experiment)
Distinguishes "my tweak broke it" (H5 false) from "the volume instance matters" (H3).
